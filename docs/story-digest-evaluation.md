# Event Synthesis Prompt Evaluation

The event overview digest shown on event pages (`/story/<id>`) is generated by `industry/prompts/story-digest.md`. Before modifying this prompt, run existing and candidate prompts side-by-side on the same set of real events for manual comparison, rather than judging subjectively.

## 1. Prepare Cases

```bash
node --env-file=.env scripts/eval-story-digests.ts --stories <storyId>,<storyId> --out .data/story-digest-cases.jsonl
```

The story ID is the path component from the URL `/story/<id>`. Exporting only reads from the database and does not make LLM calls or mutate records. Articles are selected according to the exact same rules used in production (excluding incidental mentions, general roundups, retracted articles, or unpublished items).

Each line in the exported file represents one event case. To test incremental updates when new reports arrive, change `inputMode` to `incremental`, providing `story.previousDigest` and `knownArticleIds`.

## 2. Side-by-Side Comparison

```bash
node --env-file=.env scripts/eval-story-digests.ts --cases .data/story-digest-cases.jsonl --system my-candidate.md
```

- Each case runs once with the current prompt and once with the candidate prompt: using the same model (default is current Story Digest model, configurable via `--models`) and identical inputs.
- Candidates follow the same template syntax as `industry/prompts/`: `{{siteName}}` for site name, `{{> filename}}` for shared partials.
- Safety check: prints the total number of calls (`cases × models × prompts`). If it exceeds `--max-calls` (default 18), execution halts before making any requests.
- Repeated executions reuse receipts to prevent redundant spending.

Results are output to `.data/eval/`: one JSON file and one Markdown file displaying side-by-side titles, synthesized summaries, token consumption, and receipt IDs.

## 3. Human Evaluation Checklist

Do not rely on automated LLM-as-a-judge scores. Review manually:
- Does it lead with the core change and current conclusion, rather than merely repeating the timeline chronological sequence?
- Is it free from marketing hype and generic filler?
- Are constraints (eligibility, pricing, quotas, geographic limits) accurately attributed to their respective entities?
- Does it strictly stay within facts mentioned in source reporting, without meta-commentary (e.g. "The article did not disclose...") or leaking prompt instructions?
- In correction/rewrite modes, are obsolete claims completely eliminated?

## 4. Applying Prompt Changes

Changing a prompt version does not automatically rewrite past event digests. Digests regenerate only when underlying articles change, or when new reports arrive (triggering incremental synthesis).

To immediately rewrite specific stories with the updated prompt:

```bash
node --env-file=.env --input-type=module -e '
const { rewriteStoryDigest } = await import("@aihot/backend/events/corrections");
const { sql } = await import("@aihot/backend/db");
const [s] = await sql`SELECT id FROM stories WHERE public_id = ${"<storyId>"}`;
if (!s) throw new Error("Story ID not found");
console.log(await rewriteStoryDigest(s.id, "Story digest prompt updated", "ops-script"));
await sql.end();'
```
