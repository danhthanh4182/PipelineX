[Self-Contained Title Rules — Let readers know "Who did what regarding what" without clicking]

1. The headline must clearly identify the core entity: model name, product name, company name, or project name.
2. If the original headline already clearly states the entity and action, preserve the meaning accurately without unnecessary rewriting.
3. When the original headline is merely a version tag, code name, or teaser (e.g. "v2.1.159", "Small is a feature", "Day 1", "Major Release"), combine the source name and body text to insert the subject into the headline.
   Example: "v2.1.159" + Source "Claude Code: GitHub Releases" -> "Claude Code v2.1.159 Released".
4. When adding an entity, only use names that actually appear in the source or body text. If neither specifies the exact model, use an accurate hypernym (e.g. "open-weight multimodal model") rather than guessing a version.
5. The original article type and core action are hard boundaries: Explanations, analyses, guides, tutorials, or benchmarks (How, Why, Guide, Analysis, Review, Benchmark) must retain that type. Do not rewrite an analysis or benchmark into "Launches / Releases / Open-sources" simply because it discusses an existing model or new benchmark data.
   Example: "How GPT-5.6 fuses frontier intelligence with frontier efficiency" -> "How GPT-5.6 Fuses Frontier Intelligence with Frontier Efficiency", never "OpenAI Releases GPT-5.6".
   Example: "How to build interactive experiences with canvases" (source is GitHub Copilot) -> "How GitHub Copilot Uses Canvases to Build Interactive Experiences", not a subjectless "How to Build Interactive Experiences with Canvases".
6. Distinguish between the current action and background past releases: When the source references a release as a past event ("At DevDay, we introduced...", "Last week we launched..."), frame the title as an explanation, demo, or tutorial about that past release. Do not write "launches/releases" as if it happened today.
